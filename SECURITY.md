# Security Policy

This document outlines the policy for reporting security vulnerabilities in the Valix validation framework.

---

## Supported Versions

We actively monitor and patch security vulnerabilities for the following versions of Valix:

| Version | Supported |
| --- | --- |
| `1.0.x` | :white_check_mark: Yes |
| `< 1.0.0` | :x: No |

---

## Reporting a Vulnerability

**Please do not open a public GitHub issue for security vulnerabilities.**

If you discover a potential security vulnerability in Valix, please report it privately:

1. **Email:** Send a detailed description of the vulnerability to [dev.sanjayofficial@outlook.com](mailto:dev.sanjayofficial@outlook.com).
2. **Details to Include:**
   * A description of the vulnerability and its potential impact.
   * A minimal, reproducible code example showing how the vulnerability can be triggered.
   * Details of your execution environment (Kotlin version, KSP version, JVM/KMP target platform).
3. **Response Time:** We will acknowledge receipt of your vulnerability report within 48 hours and work with you to patch the issue before making it public.
